# ADR-0003 벌점 이력과 재전송 처리

> 상태: Active
> 적용 범위: ERP 벌점 API, `PenaltyLog`
> 검토일: 2026-09-28
> 문서 담당자: 프로젝트에서 지정 필요

## 배경

길드별 벌점과 취소 감사 기록을 보존하면서 요청 재시도가 중복 부여로 이어지지 않아야 한다. 포인트 내역의 복합키는 벌점 취소 대상으로 쓰기 어렵다.

## 결정

- 독립 `id`와 `(bot_id, request_id)` 유니크 키를 사용한다. 동일 ID의 동시 재전송은 DB의 `INSERT ... ON DUPLICATE KEY UPDATE id = id`로 직렬화한다. 내용이 다르면 409, 같으면 현재 상세를 반환한다. 기록은 운영자가 삭제하기 전까지 보존한다.
- `requested_occurred_at`으로 시간 생략과 명시 입력을 구별한다. 자동 생성된 `occurred_at`은 재시도 시 바꾸지 않는다. UTC 밀리초 정밀도로 저장한다.
- 취소는 `status=CANCELED`, 취소자·시각·사유를 기록하고 누적에서 제외한다. 재취소는 최초 감사 정보를 유지한다.
- 현재 1점만 허용하고 추후 사유별 고정 점수를 위해 DB는 1~100점을 허용한다. 당장은 채널 ID를 관리자가 입력한다.
- 누적은 `[now - 30일, now)`의 `ACTIVE` 점수를 채널과 무관하게 합한다. 순위에는 현재 방의 재적 회원만 표시한다. 이력 페이지 점수는 대상자들을 일괄 집계한다.

## 검토한 대안과 영향

회원 행에 점수를 저장하면 취소·시간 경계에서 재계산이 필요하므로 조회 시 집계한다. 물리 삭제는 감사 기록이 없어져 제외한다. 새 테이블만 추가하므로 봇의 기존 쓰기는 변경하지 않지만 운영 DB에는 수동 migration을 먼저 적용해야 한다. 운영 데이터량에서 인덱스와 조회 계획을 검증한다.
